# Data modules

## Canonical (never change the schema)

### `photographyManifest.ts`
- **81** photographs, **16** albums, **10** collections.
- `SPHERE_SELECTION` — **36** curated records in sphere-slot order.
- Helpers: `getPhoto`, `getAlbum`, `getAlbumPhotos`, `getAlbumCover`, `getCollectionTitle`,
  `collectionSourceUrl`, `ARCHIVE_SOURCE_URL`.
- `source_url` is authoritative for the pristine original. Never rebuild it.

### `filmStills.ts`
- **79** stills: *Delusion of Negation* (29) and *Zakia's Clock* (50).
- `FilmStill` fields: `id`, `title`, `film`, `year`, `format`, `note`, `url`.
- `FEATURED_FILM` supplies the featured project's copy.
- `url` is authoritative for the pristine original.

## Display derivatives

### `previewAssets.ts` — AUTO-GENERATED
Base64 WebP previews used by gallery cards. Generated by:

```bash
node scripts/generate-previews.cjs
```

Do not hand-edit. It is intentionally a `.ts` file so the previews survive environments that do
not preserve binary asset folders.

### `birthPermitPreviews.ts` — AUTO-GENERATED
43 baked previews for The Birth Permit ribbon frames. Regenerate with
`node scripts/generate-birth-permit-previews.cjs`. Masters remain the viewer source.

### `previews.ts`
Accessors over the baked data:

```ts
photoPreviewUrl(id)
filmPreviewUrl(id)
hasPhotoPreview(id)
hasFilmPreview(id)
```

Returns an empty string when unknown; callers fall back to the master.

## Data flow

```text
photographyManifest ─┬─> ScrollSphere ──> previewAssets (cards)
                     │                 └> masters (upgrade + viewer)
                     └─> PhotographyGallery ──> previewAssets / masters

filmStills ─┬─> FilmRibbonPair ──> FilmSpiral ──> previewAssets (frames)
            └─> FilmDetail ──> masters

index.html (bootstrap) ──> useDeviceLayout ──> <html data-layout>
```
